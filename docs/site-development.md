# Working on the documentation site

Build it with `uv run nox -s docs_build` and preview with `uv run --group docs zensical serve`. Publishing is covered in [releasing.md](releasing.md#documentation-site).

- Zensical builds every file in `docs/site/` and cannot exclude any, so a file single-sourced elsewhere gets in by a file the build copies or generates into a gitignored spot (in `_build_docs` in the noxfile) or by a `pymdownx.snippets` include — never by a committed second copy.
- `docs/pytest-given-diagram.svg` and `docs/pytest-given-diagram-dark.svg`, the README's light and dark diagram, are derived with the font embedded and the colour tokens resolved. The light one stays light whatever the reader's colour scheme, because PyPI drops the README's dark `<source>` and keeps its page light. After editing the source SVG (`docs/site/assets/pytest-given-diagram.svg`) or its tokens, run `uv run nox -s diagram` and commit the result.
- `docs/site/assets/report-screenshot-{light,dark}.png`, shown on the README and the Home page, are captured by hand: the Hotel booking report at a 1120×588 viewport and device scale 2, with *Cancelling a paid booking refunds it and notifies the guest* expanded, one capture per setting of the report's theme switch. Retake both when the report's look changes.
- The site self-hosts its fonts so a visitor's browser contacts no third party — keep `font = false` in `zensical.toml` and don't `@import` a font CDN. Only the italics live in `docs/site/assets/fonts/` (latin subsets from Fontsource); a new face gets its `.woff2` there and its copyright line in that folder's `LICENSES.txt`.
